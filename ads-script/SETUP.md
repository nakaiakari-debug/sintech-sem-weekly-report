# Ads Script セットアップ手順

Google広告 UI に SEM週次データ書き出しスクリプトを設置する手順。

## 前提

- 対象クライアントのGoogle広告アカウントに管理者権限でアクセス可能
- 書き出し先のGoogle Sheet（デイリーレポート）が既に存在し、Ads Scriptからの書き込み権限がある
- そのSheetに `検索クエリ_raw` / `広告アセット_raw` タブが空でも存在する（初回はスクリプトが作成するのでなくてもOK）

## 手順

### 1. スクリプト作成
1. Google広告にログイン → 対象アカウントを選択
2. 「ツールと設定」→「一括操作」→「スクリプト」
3. 「＋新しいスクリプト」

### 2. コード貼り付け
1. `daily_export.js.template` の全文をコピー
2. Ads Scriptエディタに貼り付け
3. 冒頭 3定数を案件の値に置換:

```js
const SPREADSHEET_URL = 'https://docs.google.com/spreadsheets/d/{SHEET_ID}/edit';
const SHEET_SEARCH_QUERY = '検索クエリ_raw';
const SHEET_AD_ASSET = '広告アセット_raw';
```

置換値は `config/clients/<client_code>.yml` の以下を使用:
- `SPREADSHEET_URL` ← `data_source.sheet_id` を `https://docs.google.com/spreadsheets/d/{sheet_id}/edit` の形に埋め込む
- `SHEET_SEARCH_QUERY` ← `data_source.search_query_tab`
- `SHEET_AD_ASSET` ← `data_source.ad_asset_tab`

### 3. 承認と初回実行
1. 「実行」ボタンをクリック
2. **Google認証ダイアログが出る**ので、対象Sheetへのアクセスを承認
3. Loggerで以下を確認:
   - `アカウント名: <対象アカウント>`
   - `取得期間: YYYY-MM-DD ～ YYYY-MM-DD`（月曜実行なら「先々週月〜先週日」）
   - `検索クエリ書き込み完了`
   - `広告アセット書き込み完了`
4. Sheetを開き、対象2タブに14日分のデータが入っていることを確認

### 4. スケジュール設定
1. 「スケジュール」タブ → 「＋新しいスケジュール」
2. 頻度: **毎週月曜 07:00** JST
   - `07:00` or `07:30` を推奨（RemoteTrigger発火時刻9:00 JSTより前）
3. 「保存」

### 5. 初回スケジュール実行の確認
翌週月曜7:00 JST 以降にログを確認し、正常発火していることを検証。

---

## ⚠️ 既知のトラブル

### Silent skip（コード編集後の初回スケジュールが動かない現象）

**症状**: コード保存直後、次回スケジュール発火時刻になっても発火せず、ログにも何も残らない。

**原因**: Ads Script側の内部スケジューリングポインタがコード保存でリセットされることがあり、初回だけスキップされる。

**復旧手順**:
1. スケジュール頻度を別の値に変更（例: 週次→日次）→ 保存
2. すぐに元の週次に戻す → 保存
3. 「今すぐ実行」で手動発火し、承認確認
4. 次回スケジュールで自動発火することを確認

コード編集を伴う変更のたびに毎回この手順を踏むこと。**単に保存だけしても危険**。

### タイムゾーンバグ（旧バージョンで発症）

**症状**: 書き出し期間が意図の1週間前にズレる（例: 8/10実行時に 7/27-8/9 を期待するが、実際は 7/21-8/3 になる）。

**原因**: `today.getDay()` がAds Scriptサーバ時間（UTC）基準の曜日を返し、月曜JST早朝=日曜UTC深夜と判定されて `dow === 0` 分岐に落ちる。

**対策**: このリポジトリの `daily_export.js.template` は修正済み。`Utilities.formatDate(now, 'JST', 'u')` でJST基準ISO曜日を取得。

### `[使用不可]` キャンペーンのみ検出

**症状**: エクスポート結果が全ゼロ、または特定キャンペーンだけ欠損。

**対応**: `campaign.status = 'ENABLED'` フィルタを追加すべきかを検討。ただし停止直後のキャンペーンの実績を追跡したい場合はそのままでよい。
