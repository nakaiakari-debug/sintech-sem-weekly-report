## 1. Ads Script のタイムゾーンバグ

**症状**: 書き出し期間が意図の1週間前にズレる。
- 例: 8/10 07:22 JST実行時に、期待 `2026-07-27 ～ 2026-08-09`、実際 `2026-07-21 ～ 2026-08-03`

**根本原因**: `new Date().getDay()` がAds Scriptサーバの実行時タイムゾーン基準の曜日を返す。
月曜7:22 JST = 日曜22:22 UTC → `dow === 0` に判定 → `daysToLastSunday = 7` 分岐に落ちて、末尾が「前々週日曜」にズレる。

**対策**: `ads-script/daily_export.js.template` は修正済み。`Utilities.formatDate(now, 'JST', 'u')` でJST基準ISO曜日を取得。

**検算方法**:
- Ads Script実行ログの `取得期間: YYYY-MM-DD ～ YYYY-MM-DD` が「先々週月曜〜先週日曜」になっているか確認
- 月曜10:00 JST時点でシート `検索クエリ_raw` 末尾の `segments.date` が「先週日曜」になっているか確認

## 2. Ads Script コード編集後の silent skip

**症状**: コード保存直後、次のスケジュール発火時刻になっても発火せず、ログにも何も残らない。

**根本原因**: Ads Script側の内部スケジューリングポインタがコード保存でリセットされることがあり、初回だけスキップされる。

**復旧手順**:
1. スケジュール頻度を別の値に変更（例: 週次→日次）→ 保存
2. すぐに元の頻度に戻す → 保存
3. 「今すぐ実行」で手動発火し、承認確認
4. 次回スケジュールで自動発火することを確認

**注意**: 単に「保存」だけでは silent skip の可能性が残る。コード変更後は必ず上記手順を踏むこと。

## 3. Google Drive MCP の silent truncation

**症状**: `mcp__claude_ai_Google_Drive__read_file_content` で大きな Sheet を読み込むと、警告なく途中で打ち切られる。

**根本原因**: `read_file_content` は「LLM向けの自然言語表現」に変換した文字列を返す設計で、数MB超のSheetは context制限に触れて silent truncation される。エラーメッセージも警告も出ない。

**過去実例**: 2026-08-03 SHERPA週次リカバリで、4000行超のSheetのうち約200行しか取れず、当週データが完全欠損してリカバリに数時間を溶かした。

**対策**: 必ず `mcp__claude_ai_Google_Drive__download_file_content(exportMimeType="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet")` を使う。xlsx実体をローカルに保存してから openpyxl でパースする。

**注意**: `download_file_content` の応答が context制限を超える場合は自動的にファイル保存される（`/home/.../tool-results/*.txt`）。エラー扱いでもデータは正常保存されている。保存パスから `jq -r .content | base64 -d` で xlsx を復元。

## 4. Notion MCP に削除機能がない

**症状**: 誤って作成したページや古いバージョンのページを Notion MCP で削除できない。

**対策**:
- タイトルの冒頭に `[旧・要削除] ` プレフィックスを付与（`notion-update-page` の properties で対応）
- ページ本文の冒頭に赤 callout で「⚠️ 廃止版。最新版は<新ページ>を参照」を追加
- Notion Web UI 側でユーザーが手動削除するのを待つ

**運用ルール**: リカバリ・訂正時は必ず「旧ページを[旧・要削除]化 → 新ページ作成」の2ステップを踏むこと。旧ページを放置すると混乱の元。

## 5. Slack MCP に削除・編集機能がない

**症状**: 誤投稿を Slack MCP で削除・編集できない。

**対策**:
- 訂正投稿を同スレッドに追加投稿する（`⚠️ 直前投稿は誤情報です。正しくは以下：`）
- 元投稿はSlack Web UI 側でユーザーが手動削除

**リカバリ時のテンプレ**:
```
⚠️ *前投稿（<時刻>）はデータ欠損版のため無視してください*。<原因を1行>、完成版を再投稿します。
```

## 6. Drive アップロードのサイズ限界

**症状**: `mcp__claude_ai_Google_Drive__create_file` に base64 で数百KB以上を渡そうとするとエラー、または実質的に不可能。

**根本原因**: `base64Content` はインラインパラメータで、大きなペイロードは LLM の tool call サイズ制限に触れる。

**対策**:
- 100KB未満のxlsx → MCP `create_file` で問題なくアップ可
- 100KB以上 → `rclone` などのCLIツールに切り替え
- `rclone copy <local> gdrive: --drive-root-folder-id=<folder_id>` で直接アップロード可能（要 rclone gdrive 設定）

## 7. 考察の起点として議事録参照が必須

**運用ルール**: 週次レポートの「所感」「推奨アクション」は、必ず対応案件の直近MTG議事録を先読みしてから組む。数値解釈だけの一般論・教科書的示唆は禁止。

**Why**: 議事録には「今クライアントが何を気にしているか」「何が既に議論済みで再提案しても意味がないか」「次にどこに動きたがっているか」が入っており、これを踏まえないと考察が的外れになる。

**How**:
1. `config.notion.mtg_notes_parent_page_id` 配下から直近1ヶ月の議事録を検索
2. 主要論点3つ（決定事項/懸念/次回宿題）を抽出
3. 数値観察と紐付けて所感を組む（例: 「議事録で議論されたX論点は、当週のY数値傾向とこう繋がる」）
4. アウトプット末尾に「参照議事録: <日付・タイトル・URL>」を明示

議事録が過去1ヶ月以内に無ければ「該当議事録なし」と明記して数値ベース所感で進める（ユーザーに一言申告）。

## 8. お盆・GW等の連休期間の扱い

**症状**: 連休週は配信数（COST/CV/IMP）が有意に減少するため、単純な前週比が誤解を招く。

**対応**:
- 「配信減が意図的削減か自然減か」をクライアントに確認（休暇期間中の予算調整の有無）
- CV確定にラグがある可能性を注記（Googleは通常数日〜数週間のアトリビューションウィンドウ）
- 前週比の悪化は「連休影響として保留」と明示、翌週データで再評価

**運用ルール**: 連休を含む週の所感には必ず「連休補正: 施策判断は保留」を1行明記すること。

## リカバリ手順テンプレート

### ケース1: Ads Script書き込み欠損（発火失敗 or 期間ズレ）
1. Ads Script 側の状態確認（スケジュール履歴・最終実行ログ）
2. コード編集を伴った場合は §2 の silent skip 復旧手順
3. Ads Script手動実行 → シート14日分書き込み確認
4. RemoteTrigger を手動発火 or ローカル `/sem-weekly-report` スキルで再生成

### ケース2: RemoteTrigger完走したがデータ欠損
1. シートに当週データがあるか確認
2. なければ Ads Script側の問題 → ケース1へ
3. あれば download_file_content の silent truncation を疑い、download_file_content(xlsx) 方式でリカバリ
4. 旧Notionページを `[旧・要削除]` 化 → 新ページ登録 → Slackに訂正投稿

### ケース3: 前週比較の数値がおかしい
1. シートに14日分（当週7日+前週7日）データがあるか確認
2. Ads Script `getLast2WeeksRange` のタイムゾーンバグを疑う（§1）
3. スクリプトが古い版なら修正版に差し替え、§2 の silent skip 復旧手順を実行
